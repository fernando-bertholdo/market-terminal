Skill & hook

  • check-teammate-idlehookDetecta >5 arquivos não commitados em teammate

03 · Scorecard de Confiabilidade

A prova da cobertura

Cada dimensão de qualidade cruzada com os quatro mecanismos de confiabilidade. Quanto mais cheia a célula, mais forte a garantia — e onde é fraca, o template é honesto sobre isso.

7 Gates bloqueadores recusam avançar sem evidência
3 Hooks automáticos rede de segurança sem ação humana
7 Rules path-targeted carregam só no contexto certo
100% Verificação por evidência verify: steps executáveis no DoD
Dimensão Automaçãohook Gatingbloqueia Rastreabilidadeauditável Continuidadesobrevive
Qualidade de código pre-commit + hook pre-commit-check commits atômicos —
Testes hook TaskCompleted test gate verify: steps —
Segurança secrets scan hook bloqueia rule path-targeted —
Planning / escopo skills DoR + DoD verification reports CONTEXT.md + handoff
Documentação manual links no DoD audit-architecture SSOT Projeto.md
Scripts / tooling cruft hook INDEX gate INDEX.md vivo taxonomia fechada
Multi-repo / ecossistema skills manuais — Sync-ID bidirecional Changelog Local
Forte (automático/gate) Presente (skill/estrutura) Fraco/manual (honesto)

Por que mostrar as células fracas? Porque confiabilidade real inclui saber onde o sistema não protege automaticamente. Sincronização entre repos e documentação dependem mais de disciplina humana — e o template deixa isso explícito em vez de fingir cobertura total.

04 · Longevidade & Multi-domínio

Por que aguenta anos, em qualquer domínio

Alta complexidade e longevidade exigem mais que gates pontuais. Quatro propriedades estruturais fazem o template resistir ao tempo e atravessar domínios sem reescrita.

★

Single Source of Truth

documents/core/Projeto.md é a fonte única. Technical e strategy são suplementares, sempre com backlink. Em conflito, Projeto.md prevalece — não há ambiguidade sobre o que é verdade.

◍

Domain-agnostic por construção

Rules path-targeted carregam só quando o arquivo relevante é tocado. Placeholders neutralizáveis e detecção stack-aware (Python, Node, Go, Rust) deixam o mesmo processo servir fintech, saúde, dados ou web.

⎌

Rastreabilidade fim-a-fim

Decisão → Roadmap → TODO (verify:) → CONTEXT.md → commit atômico → verification report → reconcile → archive. Cada elo é auditável anos depois. Sync-ID rastreia mudanças entre repos.

⧉

Isonomia de 3 camadas

.claude/, .codex/, .agents/ mantêm as mesmas rules e skills. O projeto não fica refém de uma ferramenta — Claude Code, Codex, Aider, Gemini CLI leem o mesmo processo.
